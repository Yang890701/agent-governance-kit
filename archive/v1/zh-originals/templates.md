# TEMPLATES — 委派 prompt 模板（直接抄，填 `<>`）
> 制定 2026-07-04（D041 三件套→四件套，各模板增【禁區】）；後續更新看 git（D044）。配 DISPATCH.md 用。每個模板自帶四件套；「回報合約」原文照貼進 prompt 結尾，不要省。**禁區只有使用者能放寬**；沒有額外禁區也要寫「無」。

## 共用回報合約（每個委派 prompt 的結尾都貼這段）
```
【回報格式】你的最終回覆只能包含：
1. 結論（≤10 行）
2. 證據清單：檔案:行號，或 指令＋輸出關鍵行
3. 長產物寫到檔案，回報絕對路徑
4. 你做了什麼驗證（一行）
不要貼整個檔案內容，不要過程流水帳。
```

## 1) 搜尋／定位　→ `subagent_type=Explore`
```
【目標】找出 <符號/行為/設定> 的定義與所有使用點。動機：<接下來要改它/要理解它>。
【範圍】<目錄或整個 repo>。搜尋廣度：<medium｜very thorough>。
【禁區】唯讀，不改任何檔案；額外不可碰：<列出｜無>。
【驗收】每個命中列出 檔案:行號＋一行說明；若 0 命中，列出你試過的 pattern（至少 3 種寫法）。
＋回報合約
```

## 2) 實作　→ `general-purpose`，model=`sonnet`（涉架構取捨升 `opus`）
```
【目標】做出 <什麼>。動機：<為什麼／給誰用>。
【規格】輸入/輸出/邊界：<...>。先讀 <參考檔> 並遵循其慣例（命名、註解密度、錯誤處理）。
【非目標】不要引入新依賴除非 <條件>。
【禁區】不可碰：<檔案/目錄/API/資料，明確列出｜無>。禁區只有使用者能放寬。
【驗收】<具體指令> 執行通過；<檔案> 內含 <關鍵內容>；不破壞 <既有 build/測試指令>。
＋回報合約
```

## 3) 重構／批次修改　→ 模式已知且 >5 檔時 model=`haiku`
```
【目標】把 <舊模式> 全部改成 <新模式>。動機：<...>。
【清單】受影響檔案：<明確列出；不確定就先用模板1派搜尋產清單>。
【禁區】清單以外的檔案一律不碰；額外不可碰：<列出｜無>。
【不變量】外部行為不得改變：改前改後 <驗收指令> 的結果必須一致。
【驗收】<build/測試指令> 通過；`grep <舊模式>` 為 0 殘留（把 grep 指令寫出來）。
＋回報合約
```

## 4) 研究／查證　→ `general-purpose`（可用 WebSearch/WebFetch）
```
【目標】回答 <問題>。動機：<這個答案會決定什麼>。
【要求】至少 <N> 個獨立來源；每個關鍵數字附出處與日期；查不到就寫「未查得」，禁止用推測補全。
【禁區】唯讀，不改本機檔案；不外送 <敏感資料｜無>。
【驗收】結論附信心等級（高/中/低＋理由一句）＋來源清單（URL＋日期）。
＋回報合約
```

## 5) 審查／驗收　→ fresh-context `general-purpose`；涉高風險（資料真實性/安全/錢/對外發布）或使用者明示重要 → model=`opus` 或 3 份 `sonnet` 多數決
```
【目標】對抗式審查 <產出/檔案/宣稱>。你的立場：預設它有錯，設法駁倒它。
【檢查面】(a) 宣稱 vs 實際——親自跑 <指令> 驗證 (b) 跨檔一致性——它宣稱的事有沒有別的檔案說相反
(c) 邊界輸入／失敗路徑 (d) <此產出特有的風險，如個資、編碼、安全>。
【禁區】唯讀審查，不代修——發現問題回報，不動被審檔案。會寫檔的驗證（build/test 會產 cache/dist）只准在可丟棄環境（worktree/sandbox）跑，否則列為「未跑」並說明原因。
【驗收】每個 finding 含：嚴重度/位置(檔案:行號)/如何重現/建議修法。若無 finding，列出你檢查過什麼才敢說沒有。
＋回報合約
```

## 使用備忘
- 目標專案根有 `CONTEXT.md`(領域術語表)→ 每個模板【目標】後加一行:`【術語】遵循 <專案根>/CONTEXT.md 的術語表用語`(D043;配 DISPATCH §2)。
- 驗收條件寫不出「可執行的指令或可 grep 的內容」→ 你還沒想清楚：先派 Plan 或 goal-definer 把規格做出來。
- 派工後 subagent 回報不符合約（貼整檔、沒證據）→ 用 SendMessage 要求照合約重報，不要自己動手補。
- 同一模板同一任務重複失敗 → 停，照 DISPATCH §4 階梯升級或換拆法（輪數門檻以該檔為準，不重抄）。

## 送出前體檢〔D046/T3〕
> 委派 prompt 寫完、按送出前逐欄過一遍；改法＝語氣保留局部改寫＋before/after，不整段重寫。
1. **模糊詞掃描**——全文抓「更好/更完整/更有質感/專業/深入」等讀來具體、實則空的詞。
2. **誤讀對照**——每個抓到的詞附一行：這詞 agent 最可能誤讀成什麼。
3. **驗收可執行性**——驗收條件寫不出可執行指令或可 grep 內容 → 打回重寫，不送（同上方使用備忘）。
4. **禁區有無**——沒列＝沒想過；無額外禁區也要寫「無」，不得留白。
5. **與四件套對齊**——目標與動機／驗收條件／禁區／回報格式（DISPATCH §2）逐項核對有無缺漏。
- 體檢有欄不過 → 只改該欄、保留其餘原文語氣，附一行 before/after（改了什麼→避免什麼後果），不重寫整篇。
- 模糊詞誤讀對照＋語氣保留改寫的完整行為，見 `agents/goal-definer.md` dispatch/brief mode（同一機制不重抄）。

## 吐槽轉指令〔D046/T5〕
> 看完產出的口頭吐槽（如「太囉嗦」「又來了」）→ 順手轉成下一輪委派 prompt 的一行，不是丟掉。
1. **抓吐槽關鍵詞**——「太囉嗦/太長」→ 下一輪禁區欄加一行「不要 XX」；「又來了/重複」→ 清單欄補一行「這次必須避開 <上次被罵的具體物>」。
2. **落點**——禁區欄／清單欄二選一（見上方模板 2/3），不新開欄位。
