# 型別積木：web-system（前後端系統開發）
> 各站在通用流程之上的加料。經驗源：一個真實前後端資訊平台的實戰（決策記錄 D001–D009）。

- **站0 訪談加問**：誰是終端使用者（年齡/裝置）？要不要帳號系統？資料哪裡來（爬蟲/人工/第三方）？有沒有法遵點（個資/金流）？
- **站1 規格必含**：頁面清單＋每頁一句話用途；資料真實性標示原則（示意 vs 真實）。
- **站2 架構必產**：API 契約（端點/請求/回應範例）＋資料模型（表/欄位）＋部署拓撲（哪個服務跑哪）。技術棧偏好參考：Vue/FastAPI/Express/PostgreSQL/render（已實戰驗證過的組合）。
- **站4 實作順序**：資料層→後端(含 fallback 讓無外部資源也能跑)→前端→整合。每層先 hello-world 驗通才長肉。
- **站5 質疑加查**：CORS/rate-limit/金鑰不入庫/PII 去識別化（permission-architect 鏡頭）。
- **站6 測試必含**：兩後端 HTTP 層 smoke＋前端 build＋**誠實資料檢查**（示意資料不得標官方/真實——血的教訓）＋跨檔一致性。
- **站7 部署 checklist**：render Blueprint（或 AWS 備援）→ 環境變數（CORS 白名單、API keys 後台填）→ 免費方案限制告知（休眠/DB 到期日記入 log.md 供未來提醒）→ 公開 URL 寫進 README 頂部。
