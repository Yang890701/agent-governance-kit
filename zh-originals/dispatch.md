# DISPATCH — 模型調度守則
> 制定 2026-07-04（同日經對抗審計修訂）；後續更新看 git（D044）。讀者：主迴圈模型（日常為 Sonnet 或 Opus）。核心思想：**把 token 花在判斷，把苦工派出去**。

## §0 本環境實際可用的模型（實測自 harness，勿憑印象）
| Agent tool `model` 值 | 型號 | 定位 | 用在 |
|---|---|---|---|
| `haiku` | claude-haiku-4-5 | 快、便宜 | 機械批次、格式轉換、照 spec 套用 |
| `sonnet` | claude-sonnet-5 | 中堅主力 | 規格明確的實作、搜尋整理、一般除錯、文件撰寫 |
| `opus` | claude-opus-5 | 強 | 跨檔架構取捨、難纏 bug、安全審查、綜合判斷、高風險驗收 |
| `fable` | claude-fable-5 | 最強 | **主迴圈日常模型**（使用者全域 settings 已設 `claude-fable-5[1m]`），但**委派不要主動指定 fable**。主迴圈是 fable 時：所有委派**必須明寫** model=sonnet/haiku，防止預設繼承把苦工跑在最貴模型上 |
- **外部執行器 `codex`**（Codex CLI，`codex exec`，**非 Agent tool 的 model 參數**）：devline 開發線的站4 實作主力與跨模型對審者（該管線明示覆蓋本表對實作的 sonnet 預設）；失敗升級路徑照 §4（連錯 2 輪→方向檢查→opus 接手）。〔2026-07-04 增，事故：devline 審計 F3——本表原無 codex 導致引用斷鏈〕
- 省略 `model` = 繼承主迴圈的模型。
- **Explore／Plan 等具名 subagent 不必指定 model**（預設繼承即可）。「找東西／掃 repo」一律用 Explore——haiku 的「批次」指照 spec 改寫，不是搜尋。
- **effort 只有兩個地方能指定**：(1) Workflow 腳本 `agent(prompt,{effort:'low'|'medium'|'high'|'xhigh'|'max'})`；(2) 自訂 agent 定義檔 frontmatter。Agent 工具本身沒有 effort 參數。
- 主迴圈模型現況：使用者全域 settings 已設 fable[1m] 為日常預設；要省成本可 `/model` 切 sonnet/opus（Opus 可 `/fast`）。本表的主要用途＝**委派時選 model**。

## §1 指揮官不下場（主迴圈鐵律）
主迴圈只做：決策、拆解、派工、驗收、跟使用者說話。
遇到下列任一 → 派 subagent，主對話只收結論：
- 要讀 **>3 個檔案**，或預估輸出 **>200 行**（估不準就看替代訊號：要動 >3 檔、想「先看看再說」、要跑會刷屏的探索——**寧可多派**）
- 掃 repo / 找符號 / 查慣例 → `subagent_type=Explore`（廣度寫 medium 或 very thorough）
- 查網頁、消化長文件 → `general-purpose`
- 批次改檔（>5 檔同型修改）→ `haiku` + 明確 spec（TEMPLATES §3）
- 規劃複雜實作路線 → `subagent_type=Plan`
自己做（不要派）：改一行、讀一個已知小檔、跑單一指令、回答使用者問題（但答題需讀 >3 檔時，仍照鐵律③派 Explore）。
會刷屏的指令自己跑但抑制輸出（`| tail -5`、`--quiet`）。

## §2 派工四件套（缺一不發）
每個委派 prompt 必含，模板見 TEMPLATES.md：
1. **目標與動機** — 要什麼＋為什麼（agent 才能自行取捨細節）
2. **驗收條件** — 可執行的檢查（某指令會過、某檔案含某段、某 grep 為 0）。**寫不出具體驗收 = 你還沒想清楚**：先想清楚，或把「想清楚」本身派給 Plan/goal-definer。
3. **禁區** — 明列不可碰的檔案/目錄/API/資料；沒有也要寫「無」（逼自己想過）。**禁區只有使用者能放寬，任何 agent（含主迴圈）都不行。**〔2026-07-27 D041 增；事故：2026-06-11 RECALL-b 收尾超出宣告的唯讀範圍（內部狀態紀錄存檔區）〕
4. **回報格式** — 照 §3 合約原文貼進 prompt。
- **附術語表路徑**〔2026-07-28 D043 增〕:目標專案根有 `CONTEXT.md`(領域術語表,devline 站0/1 產出)→ 委派 prompt 加一行「【術語】遵循 <專案根>/CONTEXT.md 用語」;沒有就略過。治 agent 自創名詞與長篇解釋(共享語言省 token)。

## §2A 無人值守／迴圈委派附加欄（四件套之外必附，D046/T2）
> 適用：委派將以無人值守／排程／迴圈形態執行（`loop`／`schedule`／Fleet 背景長跑）。前置懷疑閘：先問「這件事真的需要重複跑,還是一次性做一兩次就夠」——大多數想做成迴圈的任務,人工跑幾次更省;**不具備下列五欄就別上無人值守**。
1. **Trigger** — 什麼事件觸發(手動/CI/schedule/cron);若為自動觸發,附警語:自動觸發可能在背景悄悄燒 token,需寫預估頻率與單次成本。
2. **Hard-Stop** — 資源預算硬上限(輪數/時間/Token/連續幾輪無進展就停);超過即停,不商量,任何 agent 不得自行加碼(比照禁區位階)。
3. **Memory** — 死路紀錄:每輪至少記「做了什麼／結果／下一步／哪個方向已經沒用」,禁止悄悄重試已知死路。
4. **graded-by** — 每次 PASS 判定由誰做(自己/fresh agent/使用者),標註在產物上,不得球員兼裁判(配合 §5)。
5. **驗收 rubric 證據可追溯** — 每條驗收標準需可追溯到至少一個使用者給過的 pass/fail 範例;生不出證據就刪除該條或另找範例,不得憑空杜撰。

## §3 回報合約（貼給每個 subagent）
subagent 的最終回覆只准包含：
- 結論 ≤10 行
- 證據：`檔案:行號` 清單，或指令＋輸出關鍵行
- 長產物寫到檔案，回報絕對路徑
- 做了什麼驗證（一行）
禁止：貼整個檔案、過程流水帳。

## §4 升降級路徑
- `haiku` 失敗 **1 次** → 直接升 `sonnet`（不要讓 haiku 重試同一題）。
- `sonnet` 同一子任務**連錯 2 次** → **先過 JUDGMENT §4 方向檢查**：命中「方向錯」訊號 → 換拆法（可同時升級）；未命中 → 帶完整失敗軌跡（原 prompt＋兩次輸出＋錯誤訊息）同拆法升 `opus`。
- `opus` 卡 **2 輪** → 停。把問題寫成一頁（現象／已試／卡點），問使用者或換一種拆法。
- **暫態失敗例外**：扇出中單支 agent 的 timeout／空回覆屬暫態，可原模型重試一次；**內容性失敗**（答錯、幻覺、驗收不過）照上述階梯，不重試。
- **降級**：opus/sonnet 解出模式後，把模式寫成 spec，交 `haiku` 批次套用到其餘案例。
- **雙向停損**〔2026-08-16 D046/T2〕：同題進行中若判斷模型過度思考／小題大作（任務其實一手能做完卻仍在分層拆解）→ 當場降級，把任務縮成工作包轉便宜模型接手，不必等失敗才降級。
- 同一種做法最多重試 **2 輪**；仍失敗即為方向錯誤訊號（JUDGMENT §4），換路不加碼。

## §5 驗證分工（配合鐵律④）
- **客觀指令證據**（build／test／grep／read-back／curl）：產出者自跑即可，但必須把指令與輸出關鍵行附在回報裡；一行指令能驗的自己驗即可。
- **主觀判讀與審查類驗收**（程式碼審查、文件品質、宣稱是否成立）：必派 fresh-context 的另一個 agent，產出者不得自審。
- 高風險判斷（資料真實性、安全、錢、對外發布）→ 第二意見：不同模型再判一次，或 3 份獨立答案多數決。

## §6 工具與顧問速查
| 情境 | 用 |
|---|---|
| 單次委派 | Agent 工具 |
| **2–5 個獨立子任務** | 同一則訊息**並發多個 Agent 呼叫**即可（不需 Workflow） |
| 多階段 barrier／對抗驗證收斂／扇出 ≳6／並行寫檔（需 worktree） | Workflow（⚠️ 需使用者明示同意，如「用 workflow」／ultracode；沒有就先問一句）。**同意的有效範圍＝該次請求**；跨任務要重新確認；使用者說「以後都直接用」才視為常設同意（記入 memory） |
| 接續已存在的 subagent（有 agentId） | SendMessage |
| 領域諮詢 | agent-os 顧問（見 CLAUDE.md 速查；`subagent_type` 直呼；叫不到時見 ENV §6——鏡射下個 session 才生效） |
- 顧問典型鏈：taste-distiller（品味→rubric）→ 動工 → work-auditor（完工稽核）；workflow-decomposer（拆解）→ eval-designer（怎麼證明它好）。
- 委派給顧問同樣附四件套；顧問的產出也要過 §5 驗收。
- 在裝了 agent-os 的專案：BRAIN.md 管「路由與扇出形狀」；重試／升級／驗收以本檔與 JUDGMENT 為準（BRAIN 的 self-critique 是送出前自查，不取代驗收）。

### 找東西用哪個工具（D041 波4——化解「codegraph 優先 vs Explore 優先」歧義）
| 問題型態 | 用 |
|---|---|
| 結構性問題（符號定義／誰呼叫誰／改了會壞哪）且專案有 `.codegraph/` | `codegraph_*` 直查（主迴圈自己查，免派 agent） |
| 廣度掃檔／找慣例／不知道在哪個檔 | 派 `Explore` |
| 字面文字（字串／註解／log 訊息）且大概知道位置（≤3 檔） | 自己 Grep／Read |
| 外部資訊／網頁／長文件 | `general-purpose`＋WebSearch/WebFetch |
全域 CLAUDE.md 的「codegraph 優先」指**結構問題**；§1 的「找東西用 Explore」指**廣度掃描**——分工不衝突，照上表判。
